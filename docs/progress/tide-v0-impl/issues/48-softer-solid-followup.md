# 48: solid 덜 진하게 후속(브랜드 색 안내)

Status: done
Blocked by: 47 (solid를 덜 진하게)

## What to build

[티켓 47](47-softer-solid.md)에서 추천안대로 구현하고 [판단 보류 목록](../../tide-color-tone-impl/review-backlog.md) 「티켓 47」에 남긴 6개를 사용자가 2026-11-13 「추천안으로」 정했다. 결정을 기록하고, 바꾸기로 한 두 곳만 고친다.

1. light `text-muted` → gray-700: 유지(이미 구현됨). 기록만.
2. on-solid 흰색: 유지. red를 뺀 계열은 검정 글자 대비가 더 높지만, 색 버튼의 흰 글자 관례와 계열 사이 일관성을 앞에 둔다. 기록만.
3. 500→600 명도 간격 불균일: 유지. blue-500은 앵커 `#3183f5`라 바꿀 수 없고 600은 사용자가 고른 값이다. 기록만.
4. 브랜드 색 안내 갱신: `apps/docs` 「브랜드 색 더하기」 문서의 600 권장 범위와 예시 스케일을 Tide 600과 같은 덜 진한 solid(흰 글자 4:1 이상, ADR 0023 등급)로 고친다. 앱 브랜드 색 계열을 검사하는 코드가 on-solid × solid에 4.5를 걸면 4.0으로 맞춘다.
5. axe 4.0 별도 규칙은 `*-on-solid`만: 유지. hover·누름을 따로 표시하지 않는 이유를 접근성 기준 문서에 한 줄 남긴다.
6. 과거 티켓의 600 표: 고치지 않는다. 기록만.

## Comments

- 2026-11-13 완료.
  - **대비 검사 코드**: `packages/foundation/src/contrast.ts`의 `colorContrastRules`가 이미 `on-solid` × `solid`·`solid-hover`·`solid-active`에 4를 건다(티켓 46). `tide-color` CLI(`cli.ts`)와 `color-family.ts`는 이 규칙을 그대로 쓰고 하한을 따로 두지 않는다. CLI 테스트도 4.5를 기대하지 않는다. 그래서 코드는 바꾸지 않았다.
  - **예시 600 다시 계산**: 티켓 47과 같은 방식(sRGB ↔ OKLab, L +0.03, C ×0.85 상한 0.12, 색상 유지)으로 이전 예시 600 `#a54d7a`(L 0.545, C 0.127, 흰 글자 5.33)를 `#a85c81`(L 0.574, C 0.109, 흰 글자 4.65)로 바꿨다. 같은 계산이 Tide blue·red 600의 티켓 47 값과 한 글자도 다르지 않은 것을 먼저 확인했다. 스케일 명도 순서(500 0.621 > 600 0.574 > 700 0.489)를 지킨다.
  - **권장 범위**: Tide 8개 계열의 새 600이 L 0.573~0.577, C 0.120 이하라 600 행을 「L 0.57~0.58, C 0.12 이하, 흰 글자 4:1 이상」으로 고쳤다. 이전의 「600~900 모두 C 0.13 이하」는 700~900 행으로 남겼다.
  - **대비 확인**: 고친 예시 스케일로 `node dist/cli.js build`를 실행해 대비 쌍 34개를 모두 통과했다(임시 파일은 지웠다). 같은 출력의 `solid-hover` `#904f6f`, `solid-active` `#864a67`을 「Tide Role의 색을 바꿀 때」 예시에 옮겼다.
  - **접근성 기준 문서**: axe는 렌더된 정지 화면만 검사해 hover·누름 색을 보지 않으므로, 일시 상태의 4.0:1은 대비 쌍 검사(CI)가 맡는다고 한 줄 더했다.
  - **changeset**: 코드 변경이 없고 Storybook 문서만 바뀌어 `@tide-tds/docs` patch.
