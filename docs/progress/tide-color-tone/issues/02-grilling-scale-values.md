# 계열별 파스텔 값을 스케일에 넣는 방식 결정

Type: grilling
Status: resolved
Blocked by: 01

## Question

기준 값은 계열마다 손으로 맞춘 값이다(바탕 채도 0.02~0.07, 글자 채도 0.03~0.12). 공식으로 다시 만들면 이 차이가 사라진다.

정할 것:

- 계열별 값을 스케일 단계(예: 바탕 100, 테두리 200, 글자 950)에 직접 넣고 사이 단계를 다시 잇는지, 스케일은 두고 계열별 덮어쓸 값(`familyOverrides`)으로 넣는지
- blue는 이미 100·950이 기준과 거의 같다. 테두리(200)만 채도를 낮출지
- 두 번째 파스텔이 가리킬 값(새 단계를 둘지, 기존 단계와 gray를 섞을지)
- 앱 계열(`defineColorFamily`)이 같은 결과를 내려면 무엇을 입력해야 하는지

근거: [파스텔 색감 조사 §3](../../../research/pastel-color-tone.md)

## Answer

슬롯→단계 구조를 유지하고 50·100·200·300·950 단계를 계열마다 다시 맞춘다. 호버·클릭은 단계가 아니라 「단계 + 덮기 비율」로 계산한다. 굵은 값이 바뀐 값이다. 400·500(앵커 포함)과 gray는 그대로다. 단 amber 400은 색상각만 H 80으로 옮긴 **`#ca9734`**다(05 참고).

### light 슬롯 매핑

| 슬롯 | 값 |
| --- | --- |
| `faint` | 50 |
| `subtle` | 100 |
| `subtle-hover` / `subtle-active` | 100 + gray-950 4% / 8% |
| `subtle-border` | 200 |
| `on-subtle` | 950 (neutral은 `text-default`) |
| `solid` | 600 |
| `solid-hover` / `solid-active` | 600 + black 14% / 20% |
| `text` | 700 (지금 800) |
| `border` | 600 (그대로) |
| `on-solid` | white (그대로) |

Button outline·ghost와 목록 항목의 호버·클릭은 투명 바탕 + gray-950 4%·8%다(무채색).

### 대비

- light·dark 대비 쌍이 모두 기존 기준(텍스트 4.5, UI 3)을 통과한다. 가장 빠듯한 쌍은 green 흰 글자 × solid 4.70:1이다.
- `text`는 700이다. 600이면 무채색 호버·클릭 바탕(gray-950 4%·8%) 위에서 9쌍이 4.05~4.49:1로 미달해, 원칙 ①(「대비 기준을 통과하지 못하는 색 조합은 Semantic Token으로 만들지 않는다」)과 부딪혔다. 700은 모든 상태에서 5.15:1 이상이다(Q29).

## Comments

### 3라운드(2026-11-12)

- Q11: 슬롯→단계 구조를 유지한다. light 매핑은 `faint` 50, `subtle` 100, `subtle-hover` 200, `subtle-active` 300, `subtle-border` 200, `on-subtle` 950. 50·100·200·300·950 값을 계열마다 고친다
- Q12: 계열별 값은 조사 문서의 규칙으로 초안을 만들고 비공개 아티팩트에서 확인받은 뒤 확정한다. L 계단과 대비 쌍은 모두 지킨다. 저장소에는 확정된 Tide 값만 남긴다
- Q13: `defineColorFamily` 입력은 11단계 스케일 그대로 둔다. 문서에 단계별 역할과 권장 밝기·채도 범위를 적고, 대비 쌍 검사로 강제한다

### 4라운드(2026-11-12)

- 제품 화면 이미지를 다시 분석해 목표 범위를 고쳤다(조사 문서 갱신 예정): 파스텔 바탕 L 0.94~0.97·C 0.02~0.04, 글자 L 0.32~0.36·C 0.095~0.118(청록 계열은 0.05), 테두리 L 0.84~0.90·C 0.03~0.04
- 호버·클릭은 색을 바꾸지 않고 덮는 방식으로 바꾼다(Q18). subtle-hover = 100 + gray-950 4%, subtle-active = 8%. solid-hover = 600 + 검정 14%, solid-active = 20%. Token은 계산된 값으로 따로 두고 대비 검사를 그대로 받는다. 슬롯 규칙에 「단계 + 덮기 비율」 형태가 생긴다. 300은 어느 슬롯도 쓰지 않는다
- Button outline·ghost와 목록 항목 호버는 투명 바탕 + gray-950 4%(호버)·8%(클릭)의 무채색으로 한다(Q19)
- amber·cyan 색상각은 바꾸지 않는다(Q20)
- 값은 v2(바탕 100 L 0.945, faint 50 L 0.965, 테두리 200 L 0.875, 글자 950 L 0.33~0.36)로 확정한다(Q21). 단 아래 충돌을 정한 뒤 최종 표를 Answer에 적는다

### 5라운드(2026-11-12)

- Q22: `text` 600과 무채색 호버가 부딪혀 대비 쌍 6개가 4.05~4.44:1이 됐다. 700(예외 없음), 600 + 포인터 상태 예외, 슬롯 분리 가운데 **600 + 포인터 상태 예외(4.0:1)**를 골랐다

### 05에서 바뀐 점(2026-11-12)

- amber와 장식 yellow가 구분되지 않아 하나로 합쳤다. amber 50~200은 노랑(H 95), 300은 H 88, 400은 H 80, 500~950은 지금 amber(H 75)다. Q20의 「amber 색상각은 바꾸지 않는다」를 연한 단계에 한해 뒤집는다

### 8라운드(2026-11-12)

- Q29: 5라운드의 「`text` 600 + 포인터 상태 예외 4.0:1」을 거둔다. 예외가 원칙 ①과 부딪혔고, 600·700 견본(링크·outline 버튼, 기본·호버·클릭)을 비교한 뒤 700으로 정했다. 대비 예외는 없다
