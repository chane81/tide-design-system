# 코드 주석 규칙

주석은 코드만 읽어서는 알 수 없는 것만 짧게 적는다. 배경과 결정 과정은 ADR·티켓·문서에 있으므로 코드에 다시 쓰지 않는다. 주석은 한글로 쓴다.

## 남긴다 (1~2줄)

- **왜:** 코드만 보면 이상해 보이는 선택의 이유. `// 서버 컴포넌트는 context를 만들 수 없어 client 모듈에 둔다.`
- **함정·제약:** 지키지 않으면 깨지는 조건. `// class는 문자열 그대로 적는다. Tailwind가 빌드 결과를 스캔한다.`
- **외부 동작 우회:** 라이브러리·브라우저 동작에 맞춘 코드. 버전이 중요하면 버전만 붙인다. `// Vite 8은 사용자 조건이 기본 조건을 대체한다.`
- **근거 링크가 꼭 필요하면** 문장 끝에 `(ADR 0013)`처럼 번호만 붙인다.

## 지운다

- 코드를 그대로 풀어 쓴 주석(`// 닫기 버튼` 위의 `<CloseButton />`).
- 작업 이력: 티켓 번호, "처음에는 …였다", "티켓 25에서 바꿨다". git 이력과 티켓이 맡는다.
- ADR·문서에 있는 설명을 옮겨 적은 단락. 필요하면 번호만 남긴다.
- 확인 과정 서술: "설치본 타입 선언으로 확인했다", "대조 실험 결과". 결론만 남긴다.
- 주석 처리한 코드.

## 길이

- 한 곳에 1~2줄. 3줄 이상이 필요하면 코드를 나누거나(함수·변수 이름으로 설명), 설명을 문서로 옮기고 링크를 남긴다.
- 파일 머리 주석도 같다. "이 파일이 무엇인가"는 파일 이름과 위치가 말하므로, 쓰는 쪽이 꼭 알아야 할 제약만 적는다.

## 공개 API의 JSDoc

공개 props·함수의 `/** */`는 Storybook props 표와 IDE 툴팁에 그대로 나오는 **문서**다. 지우지 않고 다듬는다.

- 1~2줄. 무엇을 하는지, 기본값, 쓰는 쪽이 꼭 알아야 할 동작(접근성 속성 등)만.
- 구현 이유·ADR 설명은 빼고 문서 사이트(MDX)에 둔다.

```ts
// ❌
/**
 * Role. Tide Role 6개와 앱이 `RoleRegistry`에 더한 Role을 받는다. 기본값은 `primary`다.
 * 색 계열 이름(`blue` 등)은 받지 않는다. 행동의 뜻을 색으로 전하기 때문이다(ADR 0016).
 * 루트에 `data-color`로 붙어 accent 색을 정한다. 바깥 요소의 색을 물려받지 않는다.
 */
// ✅
/** Role(Tide Role + 앱 Role). 기본값 `primary`. 색 계열 이름은 받지 않는다. */
```

## 테스트

- 테스트 이름(`it("…")`)이 설명이다. 주석은 flaky 대응처럼 테스트만 봐서는 모르는 이유에만 쓴다.
