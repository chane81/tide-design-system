# 컬러

색은 용도를 나타내는 **Semantic Token**(`bg-primary-solid`)이나 **색 이름**(`data-color="green"`)으로 고릅니다.

Semantic Token은 색 자체인 **Primitive Token**(`blue-600`)을 가리킵니다. Theme(light, dark)이 바뀌면 가리키는 Primitive만 바뀌므로, Component와 앱은 Semantic Token을 씁니다.

## 쓰는 법

Role 6개(`neutral`, `primary`, `success`, `warning`, `danger`, `info`)와 **강도**로 이름을 만듭니다.

```tsx
// app/page.tsx
<span className="border border-success-subtle bg-success-subtle text-success-on-subtle">완료</span>
```

| 속성          | 이름                                         | 예                                           | neutral               |
| ------------- | -------------------------------------------- | -------------------------------------------- | --------------------- |
| 배경          | `bg-<역할>-<solid\|subtle>[-hover\|-active]` | `bg-primary-solid`, `bg-danger-subtle-hover` | 있음                  |
| 배경          | `bg-<역할>-faint`                            | `bg-info-faint`                              | 있음                  |
| 글자          | `text-<역할>`                                | `text-success`                               | 없음(`text-default`)  |
| 파스텔 글자   | `text-<역할>-on-subtle`                      | `text-warning-on-subtle`                     | 없음(`text-default`)  |
| 테두리        | `border-<역할>`                              | `border-warning`                             | 없음(`border-strong`) |
| 파스텔 테두리 | `border-<역할>-subtle`                       | `border-primary-subtle`                      | 있음                  |

## 강도

강도는 바탕이 얼마나 진한지입니다. `solid`, `subtle`, `faint` 세 가지입니다.

| 강도     | 모양                                       | 위 글자                  | 쓰는 곳                          |
| -------- | ------------------------------------------ | ------------------------ | -------------------------------- |
| `solid`  | 진한 바탕                                  | `text-on-solid`(흰 글자) | 주요 동작, 눈에 띄어야 하는 표시 |
| `subtle` | 색이 보이는 파스텔 바탕, 한 톤 진한 테두리 | `text-<역할>-on-subtle`  | 상태 표시, Alert, 보조 동작      |
| `faint`  | 가장 옅은 바탕                             | `text-<역할>-on-subtle`  | 덜 중요한 표시(Badge `faint`)    |

- `faint`는 바탕 한 자리뿐입니다. 호버·누름 Token과 전용 글자·테두리가 없습니다.
- 파스텔 글자(`on-subtle`)는 같은 색상의 아주 진한 글자입니다. `subtle`과 `faint` 바탕이 함께 씁니다.

## 호버와 누름

호버·누름 색은 기본 색 위에 정해진 색을 조금 **덮어** 만듭니다. 색상은 그대로이고 밝기만 조금 바뀝니다.

```tsx
// app/page.tsx
<button className="bg-primary-solid text-on-solid hover:bg-primary-solid-hover active:bg-primary-solid-active">
  저장
</button>
```

색이 없는 바탕(Button `outline`·`ghost`, 목록 항목, Table 행)은 `bg-hover`·`bg-active`를 씁니다. 반투명이라 아래 표면 위에 덮입니다.

```tsx
// app/page.tsx
<li className="text-default hover:bg-hover active:bg-active">설정</li>
```

## 규칙

- 강도는 생략하지 않습니다. `bg-primary`는 없습니다.
- 속성마다 쓸 수 있는 이름만 class로 생깁니다. `text-bg-primary` 같은 class는 없습니다.
- `solid` 위 글자는 모든 Role에서 `text-on-solid`입니다.
- `subtle`·`faint` 위 글자는 같은 Role의 파스텔 글자(`text-<역할>-on-subtle`)이고, neutral은 `text-default`입니다.
- `text-<역할>`은 바탕 없이 쓰는 색 글자입니다. 링크, 아이콘, `outline`·`ghost` 버튼이 씁니다.
- 파스텔 테두리는 꾸밈입니다. 입력창처럼 경계를 알아봐야 하는 곳은 `border-<역할>`이나 `border-strong`을 씁니다.
- 호버·누름 색도 Token입니다. 덮은 값은 빌드할 때 계산되어 Token에 들어 있습니다.

## 공통 Token

| 종류      | Token                                                                                                                                 |
| --------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| 표면 층   | `bg-canvas`(페이지), `bg-surface`(카드, 패널), `bg-raised`(popover, modal)                                                            |
| 글자      | `text-default`, `text-muted`, `text-disabled`, `text-on-solid`                                                                        |
| 테두리    | `border-default`(장식용 구분선), `border-strong`(입력창 등 UI 경계), `border-raised`(raised 표면 경계. light는 투명, dark는 gray-800) |
| 호버·누름 | `bg-hover`, `bg-active`(색 없는 바탕의 호버·누름. 반투명)                                                                             |
| 기타      | `bg-disabled`, `bg-overlay`(modal 뒤 막), `outline-focus`(포커스 표시)                                                                |

## 색 이름으로 고르기

요소에 `data-color`로 색 이름을 주고 `accent` class로 칠하면, 같은 class가 그 색으로 바뀝니다.

```tsx
// app/page.tsx
<p
  data-color="green"
  className="border border-accent-subtle bg-accent-subtle text-accent-on-subtle"
>
  저장했습니다
</p>
```

색 이름은 Role과 색 계열 둘로 나뉩니다. 앱도 이름을 더할 수 있습니다([브랜드 색 더하기](?path=/docs/시작하기-브랜드-색-더하기--docs)).

| 종류    | Tide 이름                                                         | 뜻   | 쓰는 Component                          |
| ------- | ----------------------------------------------------------------- | ---- | --------------------------------------- |
| Role    | `neutral`, `primary`, `success`, `warning`, `danger`, `info`      | 있음 | Button, IconButton, Link 같은 행동·의미 |
| 색 계열 | `blue`, `gray`, `green`, `amber`, `red`, `cyan`, `purple`, `mint` | 없음 | Badge, Tag, Avatar 같은 장식·분류       |

- `data-color`가 없으면 `primary`입니다.
- 동작의 뜻을 전할 때는 Role을 씁니다. 색 계열은 뜻 없이 색만 구분할 때 씁니다.
- `purple`·`mint`는 장식 계열입니다. 같은 Role이 없고 Badge·Tag·Avatar만 받습니다.
- 색 계열은 Role과 같은 슬롯 규칙을 따릅니다. `neutral`과 `gray`는 다른 색입니다. `neutral`은 dark subtle이 더 밝고, 글자와 테두리가 `text-default`, `border-strong`입니다.
- `data-color`는 `data-theme`과 같은 요소나 그 안쪽에 둡니다. 그러면 그 Theme 값을 씁니다.
- 계열 class(`bg-blue-solid`)는 없습니다. 색 계열은 `data-color`로만 고릅니다.

### 슬롯

`data-color`가 고른 색은 **accent 슬롯** 12개에 들어갑니다. 표는 슬롯마다 accent class와 가리키는 스케일 단계입니다. 단계는 Role과 색 계열에 같고, neutral만 dark subtle 3단계와 글자·테두리가 다릅니다.

## Do/Don't

### Do: 뜻이 있는 표시는 Role로 칠한다

성공·경고처럼 뜻이 있는 표시는 Role(`success`, `warning`)을 씁니다. 앱이 Role 색을 바꾸면 함께 바뀝니다.

```tsx
// app/page.tsx
<Badge color="success">완료</Badge>
```

### Don't: 장식 계열로 뜻을 나타낸다

`purple`·`mint`와 `green`·`red`는 뜻이 없는 색입니다. 같은 상태가 화면마다 다른 색이 되기 쉽습니다.

```tsx
// app/page.tsx
<Badge color="mint">완료</Badge>
```

### Don't: subtle 바탕 위에 바탕 없는 글자를 쓴다

`text-accent`는 바탕 없이 쓰는 글자입니다. 파스텔 바탕의 호버·누름 위에서는 대비가 기준에 못 미칠 수 있습니다. `text-accent-on-subtle`을 씁니다.

```tsx
// app/page.tsx
<button className="bg-accent-subtle text-accent hover:bg-accent-subtle-hover">보기</button>
```

## 그 밖의 쓰임

- gradient: 배경 Token 이름을 그대로 씁니다. 예: `from-canvas`, `to-primary-subtle`
- 그림자 색: class 없이 CSS 변수 `--tide-shadow-color`만 있습니다. 그림자 단계는 Elevation에서 다룹니다.
- Tailwind 없이: `@tide-tds/foundation/tokens.css`를 불러와 `--tide-<class 이름>` 변수를 씁니다. 예: `var(--tide-bg-primary-solid)`, Primitive는 `var(--tide-color-blue-600)`
- Tailwind 없이 색 이름: accent는 `var(--tide-accent-<슬롯>)`, 색 계열은 `var(--tide-<계열>-<슬롯>)`입니다. 슬롯 이름은 위 슬롯 표와 같습니다. 예: `var(--tide-accent-on-subtle)`, `var(--tide-blue-faint)`

## 색 스케일

계열 8개(`blue`, `gray`, `green`, `amber`, `red`, `cyan`과 장식 계열 `purple`, `mint`)가 50~950의 11단계이고, 그 밖에 `white`, `black`이 있습니다. `blue-500`이 Tide의 기준색입니다.

- 읽는 법: 계열 이름 옆은 그 계열을 쓰는 Role입니다(Role이 없으면 「장식」). 타일마다 단계, hex, OKLCH 채도(C)를 적고, 글자색은 타일 위에서 대비가 더 높은 검정·흰색 중 하나입니다. 대비비는 아래 「대비」 절에서 봅니다.
- 타일 아래 「쓰임」은 그 계열로 칠한 실제 Badge·Button·Link입니다. 장식 계열은 Badge와 accent 글자만 보입니다.
- 단계마다 맡는 슬롯은 위 슬롯 표에 있습니다. 앱 계열의 단계별 역할은 [브랜드 색 더하기](?path=/docs/시작하기-브랜드-색-더하기--docs)의 「단계별 역할」을 봅니다.
- Primitive class는 브랜드 색처럼 Semantic Token으로 표현할 수 없는 곳에만 씁니다.
- `bg-blue-500`은 Tide 값입니다. `bg-slate-500` 같은 Tailwind 기본 팔레트 class는 없습니다.

## 대비

실제로 함께 쓰는 Token 조합(**대비 쌍**)이 기준을 넘는지 light와 dark 모두 자동으로 검사합니다. 기준은 WCAG 2.x 대비비이고, 하한은 세 등급입니다.

| 등급                    | 하한  | 대상                                                                                |
| ----------------------- | ----- | ----------------------------------------------------------------------------------- |
| 글자                    | 4.5:1 | 정지 상태의 글자: 표면 층, `subtle`·`faint`, 선택 유지 바탕 위 글자                 |
| 일시 상태·solid 위 글자 | 4:1   | 호버·누름 배경(`subtle` 호버·누름, `bg-hover`·`bg-active`) 위 글자, `solid` 위 글자 |
| UI 요소                 | 3:1   | 경계, 포커스 표시, Switch thumb                                                     |

호버·누름은 잠깐 지나가는 상태라 하한을 4:1로 둡니다. 색감을 해치지 않으려는 선택이고, WCAG 1.4.3(상태를 가리지 않고 4.5:1)을 엄격하게 읽으면 그보다 낮을 수 있습니다. 실제 값은 아래 표에서 확인합니다.

### 색 이름별 대비

색 이름마다 같은 규칙으로 검사합니다. 표는 그중 가장 낮은 값입니다.

| 묶음                  | 배경                                       | 하한  |
| --------------------- | ------------------------------------------ | ----- |
| 글자                  | 표면 층, `faint`, `subtle`                 | 4.5:1 |
| 파스텔 글자           | `faint`, `subtle`                          | 4.5:1 |
| 파스텔 글자 호버·누름 | `subtle` 호버·누름                         | 4:1   |
| solid 위 글자         | `solid` 3단계                              | 4:1   |
| UI 요소               | 표면 층(경계), `subtle` 누름(Switch thumb) | 3:1   |

### 표면에 따른 주의

- `outline`·`ghost` 버튼의 호버·누름은 같은 색 `faint`·`subtle`이라 불투명합니다. 어느 표면(canvas, raised)에 놓아도 대비가 같습니다. `neutral`만 반투명 `bg-hover`·`bg-active`를 덮고, `text-default`는 canvas·raised 위 모두 4:1 이상입니다.
- `subtle` 바탕 안에 `ghost` 버튼을 두면 글자를 파스텔 글자로 바꿉니다. Alert 닫기 버튼이 이렇게 칠해집니다([Button](?path=/docs/component-button--docs) 「앱이 할 일」).

### 검사에서 뺀 Token

아래 Token은 대비 검사 대상이 아닙니다. 비활성 상태는 색만으로 나타내지 않고, Component가 `disabled`/`aria-disabled` 속성과 cursor로도 표현합니다. 파스텔 테두리는 꾸밈이라 뺍니다.
