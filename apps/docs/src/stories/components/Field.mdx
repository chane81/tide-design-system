# Field

입력창에 label, 설명, 오류 메시지를 붙이고 스크린리더 연결을 자동으로 맞춥니다.

<Canvas of={FieldStories.Basic} />

## 사용 시점

- Input, Textarea에 보이는 label을 붙일 때
- 입력 규칙(설명)이나 오류 메시지를 입력창과 함께 읽히게 할 때

## 쓰지 않을 때

- 켜고 끄는 설정 하나는 Switch가 자기 label을 가집니다.
- 입력창이 아닌 텍스트에 이름을 붙일 때는 Typography를 씁니다.

### 폼 만들기

Field를 세로로 쌓습니다. 값은 네이티브 form으로 그대로 제출됩니다.

```tsx
// app/contact/page.tsx
import { Button, Field, Input, Textarea } from "@tide-design/components";

<form action="/contact" method="post">
  <Field label="이메일" required>
    <Input name="email" type="email" />
  </Field>
  <Field label="문의 내용">
    <Textarea name="message" />
  </Field>
  <Button type="submit">보내기</Button>
</form>;
```

## 접근성

### 기본 제공

- 이름: label이 `<label for>`로 입력창 이름이 됩니다. label을 누르면 입력창에 포커스가 갑니다. `group`이면 묶음이 `aria-labelledby`로 label을 이름으로 씁니다.
- 설명·오류: `aria-describedby`로 연결되어 설명, 오류 순서로 읽힙니다.
- 오류 상태: 입력창에 `aria-invalid="true"`가 붙습니다. 색과 함께 아이콘과 메시지로도 보입니다.
- 포커스: 오류 상태에서는 포커스 중에 경계가 오류 색 2px로 두꺼워지고 오류 메시지는 남습니다.
- 필수: 네이티브 `required`로 알립니다. `*`는 스크린리더가 읽지 않습니다.

### 앱이 할 일

- label은 짧은 이름으로, 규칙은 `description`에 씁니다.
- 제출할 때 오류가 여러 개면 첫 오류 입력창으로 포커스를 옮깁니다.
- 오류 메시지는 입력하는 중보다 입력창을 떠날 때나 제출할 때 보입니다.

## Props

`div`의 props를 모두 받습니다. `ref`와 `className`은 루트 `div`에 붙고, `className`은 기본 class를 이깁니다. 루트에는 `data-invalid`, `data-disabled`가 붙습니다. 안의 입력창에 직접 준 `id`, `disabled`, `required`, `invalid`는 Field 값보다 이깁니다.
